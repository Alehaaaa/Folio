# Folio application structure and reading journey

This document maps the live application entry points and the data transitions that
must remain reliable as Folio grows. The macOS executable is built from
`Sources/Folio` by Swift Package Manager. Swift files inside subfolders are
included automatically. The iOS target is generated by `iOS/generate_project.py`:
its shared sources are explicitly listed in `SHARED`, so do not move one of those
files or add a new iOS-shared dependency without updating the project generator.

## Primary user journey

| Stage | User-facing entry | Underlying owner | Next step |
| --- | --- | --- | --- |
| Discover | Home recommendations, Search, Browse, author and series pages | `HomeView`, `FolioSearchView`, `Discovery/HardcoverBrowse.swift` | Open book details |
| Evaluate | Book detail panel | `BookFlow/BookDetailsView.swift` (macOS), `FolioMobileDetails.swift` (iOS) | Read if local; Find Source if absent |
| Find a copy | Find Source in book details | `BookFlow/FindSourceFlow.swift` and `DownloadQueue` | Background search and import; no forced navigation |
| Track retrieval | Home handoff card, Downloads, in-app notices | `BookFlow/BookJourneyCard.swift`, `DownloadingView`, `DownloadQueue` | Read or open book details after verification |
| Read | Reader window (macOS) or mobile reader | `ReaderWindow.swift`, `FolioMobileReaderView.swift` | Automatic reading position and duration updates |
| Organize and review | Book detail and My Shelves | `Shelves.swift`, book detail views, `LibraryStore` | Change reading status, rating, position, collection |

The primary button on **every book detail** follows the availability of an actual
local file: **Start Reading / Continue Reading** when present, **Find Source**
otherwise. A downloaded book belongs to Library immediately after verification;
starting to read moves an unstarted/wishlisted local book to Reading Now.

## Sources of truth and background behavior

- `LibraryStore.swift` owns imported file metadata, local reading position,
  status, shelves, collections and reading activity. Never derive the ability to
  read from a remote service status alone.
- `DownloadQueue.swift` owns persistent jobs and their stages. Background work
  must survive navigation changes and relaunch. It emits `folioDownloadReady`
  and `folioDownloadFailed` once a job reaches its terminal stage, so the main
  window can show non-disruptive actions. A verified copy is imported before a
  **Ready to Read** action appears.
- `BookFlow/AutomaticEPUBChoice.swift` owns conservative edition ranking.
  Downloads are checked against the requested title, author and language before
  being accepted as library files. `shots/check-auto-epub-selection.sh` exercises
  this actual selector.
- `Hardcover.swift` and `Goodreads.swift` own remote books/shelves. The unified
  My Shelves UI combines local and remote records but must preserve each source's
  independent status and give local copies priority for reading.
- The native reader saves local position as the person turns pages. Closing a
  linked macOS reader uses the **last saved local position** to synchronize
  Hardcover pages, and records the synced-page marker only after a successful
  request. Progress editors must update reader position as well as percentage,
  or reopening the reader will overwrite the displayed value.

## Directory boundaries

| Location | Responsibility |
| --- | --- |
| `Sources/Folio/BookFlow/` | Book detail, Find Source, EPUB selection and visible handoff states |
| `Sources/Folio/Discovery/` | Hardcover discovery tiles and Browse screen |
| `Sources/Folio/Navigation/` | Validated `folio-reader://` links, including old shelf links |
| `Sources/Folio/Preferences/` | Source-extension settings UI |
| `Sources/Folio/Development/` | Explicit environment-driven screenshot and smoke-test navigation; never normal startup logic |
| `Sources/Folio/ContentView.swift` | Sidebar, selected destination and global notices |
| `Sources/Folio/DownloadingView.swift` | Actionable queue stages and completed book handoff |
| `Sources/Folio/ReaderWindow.swift` | Reading session and local position persistence |
| `iOS/Sources/FolioMobileDetails.swift` | iPhone/iPad book details and first actions |
| `iOS/Sources/FolioMobileDownloadsView.swift` | Mobile source/download/library handoff |

Prefer a small feature file for a new subview over adding another large section
to `ContentView.swift`. Keep shared models and persistence separate from native
platform-specific views. New shared dependencies must build on both platforms.

## Validation without changing a user's library

From `app/`:

```sh
swift build -c release
sh shots/check-auto-epub-selection.sh
"$HOME/.cargo/bin/cargo" build
codesign --verify --deep --strict Folio.app
```

On iOS run `iOS/build-simulator.sh` or an equivalent isolated `xcodebuild` using
`CODE_SIGNING_ALLOWED=NO`. To inspect UI flows without touching real library
data, launch a signed preview copy with `FOLIO_DATA_DIR=shots/testdata` and the
documented screenshot environment flags in `Development/FolioLaunchDiagnostics.swift`.
